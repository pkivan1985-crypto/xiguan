# R5.1 成品化界面实施计划

**目标：** 将已确认的 R5.1 Figma 精修稿落实到现有手机优先 PWA，同时保持本地数据、记录规则与路由行为不变。

**范围：** 今天主页、统一习惯列表、跑步详细记录页、底部三项主导航。只做现有能力的层级、文案、图标与尺寸调整，不新增后端、账号、云同步或发布动作。

## 任务 1：锁定界面意图

- 更新今天页测试：进度首行只显示数字比例，保留无障碍进度说明。
- 更新习惯面板测试：跑步等带详情的数量型习惯提供“详情”和 44px 单圆打卡；其他类型保留既有快捷记录。
- 更新底部导航测试：标签保留给读屏器，但视觉上只显示三个通用图标。
- 增加跑步详情的成品化文案与结构检查。

## 任务 2：落实今天主页精修

- 压缩顶部日期、周历、进度与卡片间距。
- 将跑步卡改成详情入口与单圆打卡按钮；完成后同一按钮变绿并锁定。
- 将已完成折叠区文案简化为“已完成”。
- 降低“今日汇总 / 新建习惯”视觉权重。

## 任务 3：落实跑步详情精修

- 使用“跑步记录 + 本地日期 + 关闭”的简洁头部。
- 将实际距离、计划、完成状态和上次记录整理到一张主卡。
- 上次记录改为整行“一键沿用”入口。
- 保留时长、配速、心率和备注输入；明确提示修改详情不会取消已完成状态。
- 将保存按钮收紧为 52px 高的底部主操作。

## 任务 4：落实图标式底部导航

- 保留原路由与可访问名称。
- 视觉上只显示日历、进度、习惯三个通用图标。
- 导航总高度保持紧凑，并兼容 iPhone 安全区。

## 任务 5：验证

- 运行相关 Vitest 测试并确认先红后绿。
- 运行项目完整 `npm run verify`。
- 在 390×844 手机视口检查今天页和跑步详情页，无横向溢出、无遮挡、触控目标不小于 44px。
- 本轮实现先完成本地验收；提交、推送和部署必须取得后续明确发布授权。
