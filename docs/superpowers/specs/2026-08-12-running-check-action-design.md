# 跑步卡打卡操作简化设计

## 背景

“今天”页的跑步卡目前同时显示“详情”、减号和加号。加减号代表按固定步长修改公里数，但用户无法仅凭图标理解其用途；未记录时减号还是禁用状态，进一步增加了视觉噪音。

## 目标

- 跑步卡只保留两个明确动作：完成打卡、查看或填写详情。
- 未打卡与已打卡状态仅通过同一枚圆形勾图标表达。
- 已完成记录不能因为再次点击或修改详情而被取消。
- 不改变现有 IndexedDB 数据结构、计划值计算、详情字段或保存流程。

## 交互设计

### 未打卡

- 卡片右侧显示灰色圆形按钮，按钮内部只有一个普通勾；不得再使用带圆圈的勾图标，避免出现双圆。
- 按钮可点击，辅助标签为“打卡：{习惯名称}”。
- 点击后以当天计划值作为本次完成值，沿用现有 `entryMethod: completed` 保存流程。
- 保存进行中按钮禁用，避免重复提交。

### 已打卡

- 同一外圆按钮变成绿色，内部仍只有一个普通勾。
- 按钮禁用，辅助标签为“已完成：{习惯名称}”。
- 再次点击不会清空或重置当天记录。

### 详情

- “详情”入口保留并继续进入跑步记录页面。
- 用户可以填写实际公里数、用时、配速、心率和备注。
- 已完成后修改详情继续保留完成状态，遵循现有完成锁定规则。

### 休息日

- 继续显示现有休息状态，不显示打卡勾和详情操作。

## 实现边界

- 仅修改“今天”页数量型且具有详情页的习惯控制区及对应样式、文案和测试。
- 移除该分支中的加号、减号及固定步长快捷操作。
- 其它数量型控件、逐项清单、完成型、时长型和避免型习惯保持现状。
- 跑步详情页不改布局、不改字段、不改数据模型。

## 组件与数据流

1. `TodayHabitPanel` 根据 `scheduledToday` 和 `isCompleted(habit)` 选择休息、未完成或已完成状态。
2. 用户点击灰色勾后调用既有 `onComplete(habit)`。
3. `TodayPage` 继续把 `dailyTargetBase` 作为完成值交给 `saveDailyHabitInApp`。
4. 保存完成后重新加载当天模型，按钮由灰色变为绿色并锁定。
5. “详情”继续通过现有路由进入 `HabitRecordPage`；详情保存沿用完成状态保护逻辑。

## 异常处理

- 保存进行中禁用打卡按钮。
- 保存失败继续使用现有行级错误状态，不提前把勾显示成完成。
- 当计划值为零或数据异常时仍沿用既有保存校验，不增加新的静默修正。

## 测试与验收

- 先写失败测试，证明数量型详情习惯不再渲染加号和减号。
- 未完成时渲染可点击灰色勾和“详情”。
- 点击灰色勾只调用一次 `onComplete`。
- 已完成时渲染绿色勾且按钮禁用，不允许重置。
- 休息日仍只显示休息状态。
- 运行相关单元测试、完整工具链，并在 390 × 844 手机视口确认无溢出、触控目标不小于 44px、控制台无错误。

## 非目标

- 不新增撤销打卡功能。
- 不修改跑步计划或固定步长定义。
- 不发布、不推送、不修改版本号。
