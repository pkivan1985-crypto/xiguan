# 完成锁定与数字输入优化设计

日期：2026-08-11  
状态：用户已批准混合输入方案，等待书面基线复核  
范围：手机优先网页 + PWA；只修改当天详情保存语义和记录页数字输入体验

## 1. 目标

同时修复两项直接影响每日记录的问题：

1. 用户先点击“完成打卡”，再修改距离、配速、时长、心率、备注或其他详情时，完成状态不得被详情保存隐式取消。
2. 数字记录只要求输入数字；冒号和 `km`、`/km`、`分钟`、`bpm` 等格式字符与单位由界面固定显示。

## 2. 完成状态规则

- `entryMethod: completed` 表示用户明确确认当天完成，是独立的完成锁定。
- 详情编辑只更新实际数值与附加信息，不得把已有的 `completed` 降级成 `actual`。
- 即使修改后的实际数值低于当天计划，已有完成锁定仍保留。
- 没有完成锁定时，实际数值达到或超过当天计划，界面继续按已完成显示。
- 只有用户主动点击取消完成或删除当天记录，才解除完成锁定。
- 该保护在保存逻辑层统一执行，避免不同记录入口各自覆盖状态。

## 3. 混合数字输入方案

### 3.1 配速

- 使用两组数字框：`[06] : [30] /km`。
- 每组最多两位，只唤起数字键盘。
- 第一组输入两位后自动进入第二组；第二组只允许 `00` 至 `59`。
- 冒号和 `/km` 固定显示，用户无需输入。
- 删除第二组全部内容后再次退格，可返回第一组继续修改。
- 已保存值和“沿用上次”继续显示为标准 `06:30 /km`。

### 3.2 其他数值

- 距离保持单一数值框，允许小数，右侧固定显示 `km`。
- 时长只输入数字，右侧固定显示“分钟”。
- 心率只输入数字，右侧固定显示 `bpm`。
- 保留“上次记录”“今日计划”“3 km”“5 km”等快捷值。
- 不把距离、时长和心率拆成逐位验证码格，避免可变长度数值难以修改。

## 4. 交互与可访问性

- 所有可点击输入区域的触控高度不少于 44px。
- 每个输入保留可见标签，不只依赖占位文字。
- 聚焦、错误和禁用状态必须清晰；错误在对应字段附近显示。
- 配速两组数字框在视觉上属于一个字段，并向读屏软件提供完整的“每公里分、秒”语义。
- 输入时不更换组件身份，不因状态更新导致手机键盘关闭或焦点丢失。

## 5. 数据流

1. 当天页面加载行动记录，同时读取 `entryMethod`。
2. 点击完成打卡，保存目标数值并写入 `entryMethod: completed`。
3. 打开详情页时，数值与附加信息按当前记录或既定默认规则预填。
4. 保存详情时，若旧记录为 `completed`，继续保存为 `completed`；否则保存为 `actual`。
5. 返回今天页面后，根据“完成锁定或数值达到目标”计算完成显示。

## 6. 验收标准

- 完成打卡后修改任意详情，返回今天页面仍显示完成且保持锁定。
- 主动取消完成后，完成锁定解除；若数值仍达到目标，界面按数值完成规则显示。
- 配速输入 `06` 和 `30` 即得到 `06:30 /km`，不需要输入冒号。
- 秒数超过 `59` 时不能保存，并在配速字段附近说明原因。
- 距离、时长、心率均不要求输入单位。
- Android 与 iPhone 的数字键盘可正常连续输入，键盘不会每输入一个数字就关闭。
- 旧行动记录、备份格式和 IndexedDB schema 保持兼容。

## 7. 测试范围

- 保存层回归测试：`completed` 记录经详情更新后仍为 `completed`。
- 保存层测试：普通实际记录继续保持 `actual`。
- 配速解析和分组输入测试：正常输入、前导零、秒数边界、删除与重新输入。
- 今天页面测试：完成锁定、主动取消和达到目标三种状态。
- 运行相关定向测试后，再执行项目完整验证与移动端浏览器验收。
