# R4 三屏高保真忠实重做设计

> 状态：APPROVED / IMPLEMENTATION_AUTHORIZED
> 日期：2026-07-26  
> Figma：<https://www.figma.com/design/yJruZylPTz7gfKnrK5Mm32?node-id=2-2>  
> 实施边界：只重做“今天 / 进展 / 习惯”三屏及其共用视觉组件，不改变现有 IndexedDB、备份恢复、目标计算和 PWA 数据规则。

## 1. 目标

以用户确认的三张高保真图为唯一视觉标准，重做当前已经能运行但视觉偏离严重的 R4 页面。此次不再把图片当作“风格方向”，而是按相同手机视口、相同页面状态、相同信息层级逐项还原。

成功标准：

1. 三屏在 390 × 844 内容视口下与参考图保持相同版式和视觉重心。
2. 字号、间距、圆角、卡片结构、图标尺寸、颜色和状态表达均进入逐项视觉验收。
3. 使用真实 React 组件和真实业务数据，不把参考图作为网页背景，不制造只能看的静态页面。
4. Android 与 iPhone 继续共用同一套手机优先 PWA 页面。

## 2. 已选择方案

采用“现有业务逻辑不动，三屏展示层忠实重建”。

- 保留现有路由、Dexie 数据、单项即时保存、目标汇总和备份恢复。
- 重写三屏的页面结构与专用样式，提取共用的手机视觉令牌和习惯图标映射。
- 使用 `react-icons/pi` 中的 Phosphor 线性图标匹配参考稿，不使用文字符号、Emoji 或手绘 SVG。
- Figma 文件保存参考图、逐屏硬规则和全局视觉令牌，作为代码验收依据。

不采用：

- 继续复用当前通用小卡布局：它已经证明会把参考稿压缩成普通后台界面。
- 把参考图作为整页背景：不能交互、不能响应真实数据，也无法访问。
- 再设计另一套“更现代”的界面：用户已经选定视觉稿，不再进行风格改写。

## 3. 全局视觉规范

### 3.1 视口与空间

- 基准内容视口：390 × 844。
- 页面水平安全边距：16px。
- 一级区块间距：16px。
- 卡片内边距：16px；复杂主卡允许 18px。
- 主要圆角：18px；大型面板：22px；胶囊：999px。
- 底部导航有效高度：72px，加设备安全区。

### 3.2 字体

- 页面标题：24px / 700。
- 区块标题：18px / 700。
- 卡片主标题：16px / 700。
- 正文与主要数据：15—16px。
- 辅助文字：13px。
- 只有极次要元数据允许 12px；禁止再使用 9—11px 的密集小字。

### 3.3 色彩

- 页面背景：`#071417`。
- 主卡片：`#0E2027`。
- 次卡片：`#132932`。
- 主蓝：`#2594FF`。
- 完成绿：`#7AD64A`。
- 阅读橙：`#FFB03B`。
- 生活紫：`#AD78FF`。
- 主文字：`#F5F8FB`。
- 辅助文字：`#97A8B8`。
- 分隔与轨道：`#1F3841`。

卡片允许轻微深浅层次和低强度阴影，但不能用纯黑大面积空白制造“高级感”。

### 3.4 图标与按钮

- 习惯主图标：44—52px 容器。
- 底部导航图标：24px。
- 主要触控区域：不小于 44 × 44px。
- 加减、完成、播放等状态使用彩色线性图标，并保留明显的选中或完成反馈。
- 图片不承担主要页面结构；本阶段不增加大幅插图。

## 4. “今天”页面

### 4.1 页面结构

1. 顶部：标题“今天”、本地日期、设置入口。
2. 一周日期条：七列轻量排列；选中日使用蓝色竖向胶囊；有成果的日期显示绿色完成点。
3. 完成概览：`已完成 X / Y`、横向进度条、“自动保存到本机”。
4. 统一习惯主卡：全部今日习惯放在一张大型面板中，习惯之间使用细分隔线。
5. 已完成折叠行。
6. 面板下方双入口：“查看今日汇总 / 新建习惯”。
7. 三项底部导航。

### 4.2 习惯行

- 早睡/避免类：图标、名称、连续或状态说明、右侧圆形完成按钮。
- 数值类：图标、名称、今天值、累计/目标、右侧主数字和加减按钮。
- 次数类：图标、名称、当前/目标、右侧加号。
- 时长类：图标、名称、当前/目标、右侧播放或记录按钮。

业务数据不足时只隐藏不存在的第二行，不压缩整行高度，也不改变整张主卡的视觉系统。

## 5. “进展”页面

### 5.1 页面结构

1. 标题与设置入口。
2. “月历 / 目标”分段切换；默认月历。
3. 完整月历主面板：月份切换、星期、日期、成果状态和选中状态。
4. 月历面板内直接显示所选日期成果列表和“查看详情”。
5. 总规划大型面板：显示进行中的习惯数、本月成果日、两条重点目标进度和“查看全部目标”。
6. 三项底部导航。

### 5.2 数据映射

- 成果日期来自现有 `HomeDashboardModel.outcomeDates`。
- 日期成果来自现有 `HistoryModel`。
- 长期与阶段目标来自现有 `goalSummaries`。
- 没有目标的习惯不占用重点目标位置；在“目标”页签中显示“未设置目标”入口。

禁止恢复当前的三个统计小方块，它们不是参考稿结构。

## 6. “习惯”页面

### 6.1 页面结构

1. 标题、`X 个进行中 · Y 个已归档`、设置和“新建习惯”。
2. 筛选胶囊：全部 / 运动 / 阅读 / 生活。
3. “正在进行”。
4. 第一张展开主卡：身份、每日目标、长期目标、阶段目标、双进度、计划、编辑和收起。
5. 其余习惯两列小卡：图标、名称、每日目标、百分比或状态、进度条。
6. 已归档独立行。
7. 三项底部导航。

### 6.2 展开和折叠

- 首张有目标的习惯默认展开。
- 点击小卡后，该卡展开并独占整行；此前展开卡折叠。
- 分类胶囊只过滤列表，不把信息隐藏在多层分类折叠中。
- 没有目标的卡仍显示每日参考值和今日状态，不显示虚假的 `0%`。

## 7. 组件边界

建议拆分：

- `MobilePageHeader`：标题、说明、设置和主动作。
- `BottomPrimaryNav`：三项底部导航。
- `HabitGlyph`：Phosphor 图标、颜色和容器尺寸。
- `WeekDateRail`：一周日期与成果状态。
- `TodayHabitPanel` / `TodayHabitRow`。
- `ProgressSegmentedControl`。
- `ProgressCalendarPanel` / `SelectedDaySummary` / `GoalProgressPanel`。
- `HabitFilterPills` / `ExpandedHabitCard` / `CompactHabitCard` / `ArchivedHabitRow`。

页面组件只负责组合，数据转换留在现有 feature/model 层。

## 8. 状态和错误

- 保存中只锁定当前习惯的操作，不让整页变灰。
- 保存失败在对应习惯行内提示，并恢复原值。
- 空状态仍使用同一视觉框架，保留“新建习惯”主入口。
- 加载失败使用紧凑错误卡，不改变页面基础布局。
- 减少动态效果时关闭位移动画，但保留颜色和状态变化。

## 9. 测试与验收

### 9.1 功能验收

- 今天页数值、次数、时长、完成和避免类型均能保存与撤销。
- 进展页切月、选日期、查看记录和目标跳转有效。
- 习惯筛选、展开、折叠、新建和归档入口有效。
- 备份恢复、IndexedDB、历史覆盖和 PWA 离线回归通过。

### 9.2 视觉验收

每一屏必须：

1. 使用同一 390 × 844 视口和与参考图相近的数据状态。
2. 截取完整页面。
3. 将参考图和实现图放入同一张并排对照图。
4. 检查结构、字号、间距、圆角、图标、颜色、数据密度和底部导航。
5. P0/P1/P2 差异清零后才能写 `final result: passed`。

仅“功能可用、无溢出、颜色相近”不能构成设计通过。

## 10. 不在本轮范围

- 不修改正式版本号，不创建 RC。
- 不推送 GitHub，不部署 Cloudflare Pages。
- 不改变数据库 schema 或备份格式。
- 不增加账号、后端、云同步。
- 不增加大幅图片、品牌动画或 Lottie。
