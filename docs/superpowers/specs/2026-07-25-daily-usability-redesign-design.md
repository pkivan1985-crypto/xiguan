# 每日记录易用性重构设计

日期：2026-07-25  
状态：已获用户批准，进入本地实现  
范围：手机优先网页 + PWA，本地单用户、无账号、无后端、无云同步

## 1. 目标

把当前“先选六张卡、填写整批累计值、统一保存、再播放”的流程，改成更接近日常习惯应用的三页结构：

1. **今天**：打开即看到全部进行中的习惯，单项直接记录并即时保存。
2. **进展**：查看月历、指定日期的真实记录、长期目标与阶段目标。
3. **习惯**：创建、查看和整理习惯；折叠时一行两张，展开时独占整行。

成功标准：

- 用户无需理解“卡槽”或“整批成果”，进入首页即可记录。
- 每次点击只改变一个习惯的当天累计值，保存失败时该项明确提示。
- 点击本周过去日期只查看当天记录；第一阶段不开放任意历史补录。
- 旧的行动记录、目标、备份文件与 IndexedDB 表继续可用。
- Android 与 iPhone 使用同一套响应式 PWA 界面。

## 2. 最新决策与旧规则的关系

本设计以用户本轮批准的方案为最新产品决策，替代旧界面的以下规则：

- 六个固定今日卡槽。
- 手动把卡加入当天草稿。
- 整批保存后强制逐张播放。
- 首页、今日成果、我的卡套、历史四个一级导航。

以下底层规则继续保留：

- 同一习惯同一本地日期只有一条 `ActionRecord`，再次保存覆盖当天累计值，不重复累加。
- 行动记录仍驱动长期目标、阶段目标和成果月历。
- 目标完成、修订、备份恢复、离线缓存沿用现有数据事实。
- 只允许修改本地“今天”的记录；过去日期只读。

## 3. 信息架构

### 3.1 今天

- 顶部为紧凑周日期条，默认选中今天。
- 主区自动列出全部进行中的习惯，不再要求加入卡槽。
- 每张今日卡只显示：图标、名称、今天的值、短目标、主要操作。
- 支持五类记录方式：
  - 完成：一次点击完成/撤销。
  - 计数：加一、减一。
  - 数值：按预设步长增加/减少，也可打开精确输入。
  - 时长：按分钟步长增加/减少。
  - 避免：标记“今天守住了”/撤销。
- 单项操作即时写入本地数据库。
- 空状态只保留一个明确入口“新建习惯”。
- 可选的“今日小结”仅作为真实记录汇总，不阻断单项保存。

### 3.2 进展

- 顶部概览展示本月成果日、今日完成项和长期目标数。
- 月历尺寸适中，成果日有标记，当前选中日期有明确外框。
- 点击日期后显示该日真实记录；过去日期只读。
- “总规划”区展示每个习惯的阶段目标和长期目标进度，点击进入现有目标详情。
- 不制造趋势、连续天数或奖励数据；所有数字来自真实 `ActionRecord` 与目标。

### 3.3 习惯

- 顶部主动作“新建习惯”。
- 分类默认折叠，显示分类数量。
- 折叠习惯卡一行两张，仅显示图标、名称、记录类型和今日值。
- 点击卡片后独占整行，显示阶段/长期目标与进入详情的操作。
- 归档数据继续保留，不在本次加入删除功能。

## 4. 创建习惯

新建流程以最低认知负担为原则：

- 必填：习惯名称、记录方式。
- 记录方式先提供主流预设：
  - 跑步/距离。
  - 喝水/计数。
  - 阅读/时长。
  - 睡眠/完成。
  - 少刷手机/避免。
- 每个预设自带单位、步长和每日参考值。
- 长期目标、阶段目标为可选；没有目标也可以正常记录。
- 本轮不开放任意自定义单位，避免产生无法比较或恢复的数据格式。

## 5. 数据与兼容

### 5.1 数据模型

`CardTemplate` 增加非索引元数据：

- `trackingType`
- `iconKey`
- `accent`
- `defaultDailyTargetBase`
- `stepBase`

这些字段只改变模板解释，不改变 Dexie 表、索引或主键，因此数据库仍使用现有 schema version。

### 5.2 系统模板

应用每次读取时幂等补齐系统分类和模板，而不是只检查 `running`。这样：

- 已安装用户会自动得到新增预设。
- 已存在的跑步模板保持同一 ID 和版本。
- 用户卡、目标和旧备份引用不变。

### 5.3 即时保存

新增“单项今日保存”入口，复用现有事务中的：

- 数值解析和超限确认。
- 记录 upsert。
- 长期/阶段目标重新计算。
- 目标完成快照和修订记录。
- `OutcomeBatch` 审计事实。

单项保存完成后直接把该批次标记为完成，不留下阻挡页面的“待播放”提示。原批量保存代码暂时保留作兼容，不作为新 UI 入口。

## 6. 视觉系统

视觉以用户选定的第一套原型为准：

- 深青黑底、蓝色主要动作、绿色完成状态。
- 使用 `react-icons`，不使用 emoji、手绘 SVG 或大型装饰图。
- 标题克制，正文短；优先使用图标、数字和状态表达。
- 页面不再使用大幅 hero 图片。
- 图片或插画仅在确有信息价值时使用，尺寸适中；本轮核心页不需要新增图片。
- 触控目标不小于 44px，底部导航适配安全区。
- 360px、390px、430px 宽度均不得横向溢出。

## 7. 错误与边界

- IndexedDB 读取失败：页面内显示重试，不清空已有数据。
- 单项保存失败：只回滚该项的乐观状态并提示，不影响其他习惯。
- 日期在操作期间变化：拒绝保存并要求刷新今天。
- 数值超常用范围：继续使用现有二次确认机制。
- 模板或卡片关系缺失：该项显示不可用，不伪造名称或单位。
- 过去日期：只读，不显示加减或完成按钮。

## 8. 非目标

本轮不包含：

- 账号、云同步、跨设备自动同步。
- 原生 Android/iOS App。
- 社交、排行、积分、AI 建议。
- 任意历史补录。
- 删除历史数据或迁移旧表。
- GitHub 推送、公开发布、Cloudflare 部署。
