## 一、产品目标与开发边界

### 1.1 产品目标

在原软件底部增加“钱”专项入口，整合原有收入、支出、额外开支记录，并增加每月固定账单与付款打卡。

用户进入后能够直接知道：

1. 当前已登记的剩余负债是多少。
2. 选中月份要付多少、已经付多少、还剩多少。
3. 每笔账单哪一天要付、是否付清。
4. 过去哪几个月已全部付清，能查看与修改具体记录。

### 1.2 本版必须交付

- 底部第四个钱包入口与“钱”首页。
- 信用卡、贷款、固定支出三类月度账单。
- 每个项目独立日期、独立金额、最右侧独立打卡勾。
- 新增、编辑账单，开启或停止每月重复计划。
- 全页面付款登记，支持部分付款、多次付款、补录、修改与明确撤销。
- 三类小计、月度总合计、当前剩余负债。
- 页面最下方的月份完成简表及独立月份详情页。
- 原记账与额外开支的统一查看、查询和原有编辑入口。
- 本地持久化、旧数据兼容、备份恢复及必要测试。

### 1.3 不在本次范围内

- 银行连接、自动扣款、自动读取银行账单。
- 云同步、多用户、账号登录或新后台。
- 自动计算贷款利息、摊销表、自动判断用户真实银行余额。
- 投资建议、借贷推荐或信用评分。
- 无关页面重做、框架升级、替换图标库或全站重构。

现有习惯、记账、额外开支和历史查询继续保留。“钱”是聚合与账单管理入口，不擅自删除原来的习惯卡，不改变原有普通习惯的打卡统计规则。

## 二、金额口径与计算规则

金额统一按人民币展示，保留两位小数；持久化与计算使用整数分，禁止使用浮点金额累计。

| 指标 | 定义 | 说明 |
|---|---|---|
| 当前总负债 | 各信用卡债务账户最新确认欠款 + 各贷款债务账户最新确认欠款 | 按债务账户计算，不按每月账单重复累加 |
| 本月应付 | 选中月份所有有效账单计划金额之和 | 包括信用卡、贷款、固定支出 |
| 本月实付 | 关联选中月份账单的有效付款金额之和 | 跨月付款仍属于该账单的实付 |
| 本月待付 | 各账单 `max(计划金额 − 累计实付, 0)` 之和 | 不用总应付减总实付代替，防止一项多付掩盖另一项未付 |
| 月度收入 | 实际日期在选中月份的收入记录之和 | 按实际收款日期 |
| 月度支出 | 实际日期在选中月份的消费支出之和 | 包含固定支出，排除单独展示的还款 |
| 月度还款 | 实际日期在选中月份的信用卡、贷款付款之和 | 与消费支出分开，避免原消费和偿还重复计为消费 |

房租、水电、订阅等属于固定支出，不直接纳入信用卡/贷款剩余负债。固定账单未付也不自动转成贷款欠款。

同一张信用卡或同一笔贷款可以有多个月份账单，但当前总负债只计算该债务账户一次。不要把账单模板、月份实例和债务余额混成一个数字。

有债务账户未填写剩余欠款时，展示“已登记负债 ¥X，仍有 N 项金额待补充”，不把未知当成零、不宣称总额完整。没有债务账户时显示“尚未登记负债”；用户明确登记余额为零时才表示该账户已结清。

首页当前负债不随月份选择伪装成历史负债；标明最近确认时间。历史月份详情不展示没有依据的历史欠款余额。

示例：信用卡剩余欠款 12,000 元、贷款剩余欠款 58,000 元，则当前已登记负债为 70,000 元。某月信用卡应付 2,000 元、贷款应付 1,500 元、固定支出应付 2,500 元，本月应付为 6,000 元，不是负债 6,000 元。

- 每个图标具有无障碍名称，选中项沿用蓝色。

## 四、“钱”首页设计

### 4.1 页面顺序

统一标题栏 → 当前负债摘要 → 月份选择 → 月度收支摘要 → 三类固定账单 → 右下月度合计 → 月份完成记录 → 底部导航。

### 4.2 三类卡片

- 三类分别为“信用卡”“贷款”“固定支出”，视觉结构一致。
- 初次进入默认展开，方便看到实际账单；点击类别标题收起或展开，返回页面保留状态。
- 收起时仍显示类别、已付项目数、应付小计与待付金额。
- 类别右侧“+”只新增该类别项目，不同时触发折叠。
- 展开后按应付日期升序，同日按稳定顺序排列；付款后不突然移位，不自动隐藏已付项。
- 每条项目结构：日期 → 名称 → 金额 → 最右侧打卡控件。
- 每条项目拥有独立日期。同一类别的多个项目不必在同一天付款。
- 长名称允许换行，不能挤走金额和打卡控件。
- 已逾期且未付清的日期增加暖色状态及“逾期”提示。
- 空类别保留“+”和零小计，不显示一堆占位卡。

### 4.3 打卡外观与入口

- 未付：单个灰色圆形控件，可有低强调勾。
- 付清：同一位置变成单个绿色圆与单勾，禁止双圆套圈。
- 部分付款：仍非绿色完成状态，显示已付/剩余金额，允许继续登记。
- 项目名称/行主体进入单项详情；最右侧控件负责付款操作。
- 控件视觉紧凑，触控区域至少 44×44px，并与其它控件保留足够间距。
- 点击已付勾查看付款详情，不直接取消完成状态。

### 4.4 合计与页面底部

每类卡片底部小计表示应付计划金额，标签必须写清楚。三类下方右对齐显示应付、实付、待付及已付项目数。

第一版合计采用正常文档流，不悬浮覆盖内容。底部月份列表必须能够完整滚动看到，不被导航栏或手机安全区遮住。

“+ 记一笔”进入普通收支新增完整页，复用现有日期、时间、类别、账户、事项、备注能力；不能为了打开此入口，偷偷为用户新建重复习惯。具体存储接入由开发者核对现有模型后确定。

## 五、新增与编辑账单

### 5.1 字段

| 字段 | 规则 |
|---|---|
| 类别 | 从类别“+”进入时预选，新增时可调整 |
| 项目名称 | 必填，保存前去除首尾空白 |
| 本期应付日期 | 必填，选择完整年月日，决定所属月份 |
| 本期计划金额 | 必填，必须大于零，最多两位小数 |
| 债务账户 | 信用卡/贷款选择已有账户，或登记新账户；固定支出不显示 |
| 当前剩余欠款 | 新债务账户可填写，允许暂缺但明确标记；不得为负 |
| 每月重复 | 默认开启，可关闭成为单次账单 |
| 备注 | 选填 |

输入框标签放在上方，避免“左边一段文字、右边一个狭小输入框”的堆砌设计。保存是唯一主要操作，取消/返回为次要操作。

金额输入保留用户正在编辑的字符串，例如 `8.`、`8.0`；不要每次按键即格式化成 `8.00`。支持手机小数键盘连续输入，失焦或保存时校验与格式化。禁止通过更换组件 key、重复挂载或强制移焦造成每输一字键盘收起。

### 5.2 月度重复

- 项目模板生成各月独立账单，同一模板同一月份只生成一次。
- 29、30、31日遇到短月，落在该月最后一天，并给出提示。
- 模板记住原定日号；例如31日计划在2月变为月底，3月仍恢复31日，不永久漂移到28日。
- 下月金额使用已确认模板金额作为默认计划，允许单独修改当月。
- 停止每月重复只影响尚未生成的未来计划；已有账单与付款历史保留。
- 信用卡账单默认值不是银行自动账单，界面不能误导。

### 5.3 编辑范围

- 修改当月应付日期/金额，默认只作用于当前月份账单。
- 修改重复规则或未来默认金额时，清楚说明“以后月份使用此设置”，不得静默重写历史。
- 已有付款的账单更改所属月份需要明确确认；付款实际日期不随之变化，并重算原月、新月汇总。
- 不允许通过暂停未来计划，把当前未付账单自动移除以制造“已付清”。
- 删除、撤销等破坏性操作提供明确说明与确认，不能混在普通打卡点击里。

## 六、付款登记与修改

### 6.1 首次与追加付款

点击未付控件进入完整“记录付款”页：

1. 展示项目名称、所属月份、应付日期、计划金额与剩余待付。
2. 实付金额默认剩余待付金额，可修改，必须大于零、最多两位小数。
3. 实际付款日期与时间默认当前本地时间，支持过去日期补录；不能把未来付款计划当作已支付事实。
4. 付款账户可选，备注选填。
5. 信用卡/贷款可填写“付款后剩余欠款”，不填写则保持原余额与确认时间。
6. 保存成功后更新关联账目、项目状态、小计、合计与月份记录，并给出简短反馈。

未付清可以多次登记；各次付款属于同一账单，不生成重复账单。正在保存时禁止重复提交，保存失败不能先把圆变绿。

### 6.2 状态派生

| 条件 | 状态 |
|---|---|
| 累计有效实付为0 | 待付 |
| 实付大于0且小于计划 | 部分已付 |
| 实付达到或超过计划 | 已付清、绿色勾 |
| 应付日期早于今天且仍有待付 | 叠加逾期提示 |

一笔账单多付的钱保留为真实实付，但不能自动拿去填另一笔账单的缺口。

### 6.3 修改与撤销

- 已付勾和单项详情均能查看多笔付款。
- 点击付款记录进入完整编辑页，可以改金额、实际日期时间、账户和备注。
- 撤销登记使用明确操作与确认，不通过再点一次勾完成。
- 修改/撤销后重算账单、月度合计和月份完成状态。
- 若付款创建了新的账目，修改/撤销同步处理该账目；若关联的是原先已存在的账目，必须区分“解除关联”和“撤销原账目”，不能未经说明删除用户原记录。
- 修改付款备注等非金额信息不会取消打卡；只有有效付款不足计划时才变为未付清。

### 6.4 负债余额

贷款月供可能包含利息，禁止直接用整笔付款自动扣减剩余本金。信用卡也可能有新增消费，不能仅靠还款猜测余额。

使用用户最新确认的剩余欠款与时间。历史补记、修改或撤销旧付款，不自动覆盖更新的余额；涉及余额变化时提示用户重新确认。零余额代表明确登记已结清，不等于自动删除账户或历史。

本功能的打卡只是“登记已经付款”，应用不执行实际转账。

## 七、月份完成简表与详情

### 7.1 出现条件

当月必须至少有一条有效账单，且全部有效账单都付清，才算月份完成。统计对象是三类中的所有账单，不是点击三个类别标题。

空类别不阻碍其它账单完成；整月无账单不生成已完成月份。月份未到不自动完成，只有真实付款记录才能产生完成状态。

最后一笔付清时提示“6月账单已全部付清”，并在首页最下方月份简表出现一行；同月多次保存不重复生成。

### 7.2 简表结构

```text
月份完成记录
2026年6月 · 已付 ¥6,000.00              详情 ›
信用卡 ¥2,000 · 贷款 ¥1,500 · 固定支出 ¥2,500
```

- 主行：年份月份 + 三类实付总额 + 详情入口。
- 副行：三个类别实付小计，窄屏允许自然换行。
- 按月份倒序排列，不能因查看不同月份而丢失已完成历史。
- 没有完成月份时只显示简短空状态。
- 这里的金额是实付总额，不是剩余负债，也不是应付计划。

### 7.3 重新变为未完成

当月新增账单、增加应付、修改/撤销付款后立即重新计算。曾经完成的月份行保留详情入口，状态改为“待补齐 · 已付 N/M 项”，显示当前实付金额。

再次付清时恢复原行状态，不新增第二行。金额和状态来自当前有效账单与付款，不能只保存一个不再更新的完成快照。

跨月补付会更新账单所属月的完成情况；实际付款仍在收支记录中归属付款发生月。

### 7.4 月份详情完整页

标题如“2026年6月账单”。内容依次为：

1. 应付、实付、待付、已付项目数与整月状态。
2. 信用卡小计与逐项账单。
3. 贷款小计与逐项账单。
4. 固定支出小计与逐项账单。
5. 三类合计。

各项目显示名称、应付日期、计划、实付和状态，展开可查看每笔付款日期时间、金额、账户与备注。允许进入原付款编辑页。

返回恢复首页的月份、折叠状态和滚动位置；不得强制跳回今天或当前月。未完成月份同样可从月份账单区域进入详情，不必等到付清才能查看。

## 八、现有记账与额外开支整合

前期草案记录了现有 `BookkeepingEntry` 与 `ExtraExpenseLineItem` 等模型。开发时必须重新核对实际字段、存储位置、调用方和编辑流程；不能假设模型天然支持“还款”类型。

### 8.1 统一查询

“查看记录”提供：

- 年月选择。
- 收入、支出、还款筛选。
- 事项、项目名称、类别、账户、备注关键词查询。
- 额外开支继续保留原因、必要性及反思字段与原有编辑能力。
- 按实际日期时间排序，展示日期、事项、金额、类型及必要的来源标识。

原记录被展示到“钱”页不等于复制一份新账目。不同来源疑似重复只能提示，不可仅凭同名、同日、同金额自动合并或删除。

### 8.2 账单与账目关联

- 固定支出付款创建或关联一笔普通支出。
- 信用卡/贷款付款在聚合层明确识别为还款，与消费支出分开展示。
- 复用既有账目必须保留稳定来源标识；同一笔账目不能重复计算、重复关联到不同账单。
- 账目编辑引起金额或日期变化时，相关付款和汇总同步更新。
- 账单归属月与实际付款日期分别存储；跨月付款不改写账单原应付日期。
- 涉及多条记录的关联保存、修改、撤销应原子完成；失败不能留下半条付款或虚假绿勾。

开发者可按现有架构选择最小兼容实现，但必须满足上述口径，不能为了新页面另建一份不互通的账本。

## 九、数据与兼容要求

下列是逻辑实体要求，不强制指定表名或文件名；按现有工程约定落地。

| 逻辑对象 | 必须表达的内容 |
|---|---|
| 债务账户 | 稳定ID、信用卡/贷款类型、名称、可缺失的最新余额、确认时间、停止未来计划状态 |
| 重复账单模板 | 稳定ID、类别、名称、可选债务账户ID、原定日号、未来默认金额、起始月份、重复状态 |
| 月份账单 | 稳定ID、可选模板ID、所属年月、独立应付日期、计划金额、名称/类别、债务账户关联 |
| 付款记录 | 稳定ID、账单ID、整数分金额、实际本地日期时间、账户/备注、账目来源关联、有效状态 |
| 月份回看标记 | 标记该月曾完成，供重新待补齐后继续显示；状态与金额仍动态派生 |

数据约束：

- 同一模板与年月必须唯一，重复访问、刷新、离线重新进入不能生成重复账单。
- 付款提交具有去重保障，不能把用户双击变为两笔支出。
- 日期按用户本地日历处理，不因 UTC 转换移到前一天。
- 余额、账单金额与付款金额分别表达，不能复用同一字段。
- 有效付款合计决定打卡状态，不能只存一个孤立布尔值。
- 付款关联账目后只有一份有效金额事实，避免两边各改各的。

存储沿用现有本地优先架构。新增数据需要兼容旧数据与既有普通/加密备份流程；禁止通过清库、重置数据、要求用户重建所有习惯来完成迁移。

旧备份没有新字段时应使用安全默认值；新备份必须恢复债务账户、模板、账单、付款关联及月份回看标记。导入后重新计算状态，不信任过期汇总缓存。不得声称旧版软件一定能读取新版备份。

## 十、视觉与手机输入规范

- 保留现有深色青黑背景、蓝色操作、绿色完成和低对比卡片边框。
- 标题栏与今天、进展、习惯统一高度；不要重做无关页面。
- 继续使用现有 Phosphor 图标；少装饰、少重复说明，不增加大图片。
- 金额等宽数字、右对齐、固定两位小数；关键金额仍保留必要标签。
- 表单标签在上方，字段紧凑但易点按，手机输入字号避免引发自动缩放。
- 点击反馈清楚，错误显示在对应字段旁，不用“按钮灰了却不说明原因”。
- 输入时组件稳定，不自动隐藏键盘、不自动移动光标、不每次按键格式化。
- 所有主要输入页为完整页面，弹出键盘后仍能滚动到字段及保存操作。
- 未保存内容离开时提供明确处理，避免意外丢失。
- 底部内容预留导航和安全区；无额外高空白，无合计条遮住最后一行。
- 触屏、鼠标和键盘均能完成基本操作，不依赖滑动或悬停才能进入关键功能。
- 状态不只依赖颜色：有勾形状、状态或无障碍名称。
